# 변리사 트랙 설계안: AP 15단계 변리사판

- 대상: «업체 분석 → 제안 준비» 도구 (업체 분석 → 제안 준비)
- 작성: Claude, 작성 변리사 검토용 / 2026-11-04
- 근거: 허브 AP 표준, 사용 원칙, 직무발명·특허 컨셉 문서, 도구 코드 일부, 변리사 제안서
- 화법은 초안입니다. 특허 내용은 변리사가, 세무 내용은 세무사가 확인해야 합니다.

## 1. 현재 도구의 상태

"내 자격"에 변리사를 고르는 칸은 이미 있습니다. 그러나 AP 스크립트에서 확인된 변화는 02단계 한 문장과 03단계의 호칭뿐입니다.

| 위치 | 지금 | 변리사에게 생기는 문제 |
|---|---|---|
| 관계 | 기장거래처 / 소개 / 초면 | 변리사에게 맞는 "특허 고객" 항목이 없음 |
| 03 기장거래처 | "1년에 한 번 뵈면 결산 얘기만" | 변리사가 할 수 없는 말 |
| 03 초면 | "기장 영업하러 온 게 아닙니다" | 오해를 막는 말이 다름. "특허 영업" 의심이 맞음 |
| 03 명분 예시 | 외부 컨설팅 세무조사, 상속 | 세무사 경험 전제 |
| 미팅 성격 | 가결산·결산 겸 / 단독 | "특허 상담 겸"이 없음 |
| 신호 | "특허·연구소·연구전담부서" 한 칸 | 특허 유무, 규정 유무, 연구소를 구별하지 못함 |
| 직무발명 진단 | 법인만 점수 〔특허·연구소 3, 상여 2, 이익 1〕 | 특허 없는 기술 회사는 놓침 |

06~15단계 코드는 끝까지 확인하지 못했습니다. 개발 전에 전체를 봐야 합니다.

## 2. 지키는 선

기존 원칙을 그대로 따릅니다.

1. AP의 결과물은 다음 약속과 소개입니다.
2. 고객이 말한 숫자와 공개 자료만 근거로 삼습니다.
3. AP에서는 보험 상품명과 제도 구조를 말하지 않습니다. 예외로 변리사는 본업 용어인 "직무발명"을 쓸 수 있습니다(작성 변리사 결정). 세금 효과, 절차 상세, 보험 연결은 그대로 말하지 않습니다.
4. 세무 효과는 변리사가 단정하지 않고 세무사 검토로 넘깁니다.
5. 특허·직무발명 용역과 보험은 대가로 묶지 않습니다. 문서와 시점을 나눕니다.

## 3. 입력 항목 변경

자격이 변리사일 때만 적용하고, 세무사 화면은 그대로 둡니다.

**관계:** 특허 고객 / 소개 / 초면. "기장 기간"은 "거래 기간"으로 표시합니다.

**미팅 성격:** 특허 상담 겸 / AP 단독

**신호 (기존 한 칸을 나눔):**

- 회사 명의 특허가 있음
- 특허 출원 중이거나 계획 있음
- 특허는 없지만 자체 기술·시스템이 있음
- 직무발명 규정 없음 또는 모름
- 기업부설연구소·연구전담부서 있음
- 벤처인증 있음
- 사업용 부동산 매입 계획
- 핵심 개발자 이탈이나 경쟁사 모방 우려

연말 상여, 잉여금, 창업 7년 이내 신호는 기존 항목을 씁니다.

## 4. 진단: 세 가지 진입로

점수를 새로 만들기보다 신호로 진입로를 고릅니다.

| 진입로 | 신호 | 첫 대화 | PC에서 다룰 것 |
|---|---|---|---|
| A. 있는 특허 정리 | 특허 있음, 규정 없음, 상여 계획 | 발명자와 권리 관계 | 규정, 승계, 보상 절차, 상여와 비교 |
| B. 기술을 권리로 | 특허 없음, 자체 기술 있음 | 무엇을 지켜야 하는가 | 출원 계획, 그 뒤 규정 |
| C. 회사 스펙 쌓기 | 업력 짧음, 부동산 계획, 연구소 없음 | 앞으로의 자금·입지 계획 | 특허 → 연구소 → 벤처 순서 |

세 진입로 모두 PC 후반의 마지막 칸은 같습니다. 회사 가치가 오른 만큼 생기는 퇴직금, 유고 자금, 상속 재원입니다.

## 5. AP 15단계 변리사판 (A 진입로 예시)

| 단계 | 초안 멘트 | 확인할 점 |
|---|---|---|
| 01 릴렉스 | "라인에 새 장비가 들어왔네요. 작년엔 못 봤는데요." | 현장에서 본 것 |
| 02 동질감 | "직접 만드신 공정이 눈에 보이네요. 저도 기술 흐름을 따라가느라 매년 공부합니다." | 칭찬과 공통점 |

| 04 목적 | "출원 얘기도 있지만, 대표님 회사의 기술이 지금 누구 것으로 되어 있는지 같이 보려고요." | 이유 두 개 |

| 07 구체 사례 | "공개된 자료로 보니 회사 명의 특허가 [ ]건입니다." | 특허 공개 정보로 직접 확인 |

| 10 선거절 | "특허에 돈 쓸 여유가 어디 있냐고 하실 수 있습니다. 맞습니다. 다만 기술이 없는 회사는 이런 고민 자체를 안 합니다." | 승부처 |

## 6. 변리사용 저항 대응

| 저항 | 대응 |
|---|---|
| "거래하는 특허사무소가 있어요" | "그 관계는 그대로 두셔도 됩니다. 오늘은 출원이 아니라 권리와 규정 현황을 보는 겁니다." |
| "특허는 돈만 들잖아요" | 맞다고 인정하고, 지킬 기술과 아닌 기술을 나누는 것부터 제안 |
| "이름만 넣고 보상금 주면 되죠?" | "형식만 갖추면 인정받기 어렵습니다. 규정, 절차, 출원까지 맞아야 합니다." |
| "외부 업체가 빨리 도입하라던데요" | 부정하지 않고, 사후관리까지 보는 관점으로 답변 |
| "세금이 정말 줄어요?" | "대표님 조건은 세무사와 함께 확인해서 범위로 말씀드리겠습니다." |
| "결국 보험 얘기 아니에요?" | "활용할 수도 있지만 오늘 제안드리는 건 아닙니다." 부정하지 않기 |

## 7. PC와 협업

**PC 순서:** AP 복기 → 권리 현황표 → 규정과 절차 → 상여·보상 비교(세무사 검토) → 벤처 로드맵 → 진행 일정.

보험은 이 문서에 넣지 않고, 시간을 둔 별도 미팅에서 별도 문서로 제안합니다. 변리사 제안서의 3단 그림은 표현을 고쳐 이 순서에 재사용할 수 있습니다.

| 역할 | 맡는 일 |
|---|---|
| 변리사 | 특허, 발명자, 직무발명 규정, 벤처·연구소 |
| 세무사 | 공제·비과세 요건, 효과 계산, 법인세 영향 |
| 노무사 | 규정 고지와 불리한 변경 시 동의 절차 |
| 지점장·보험 담당 | 재정심사, 가입설계서, 보험 제안 |

## 8. 개발 변경 범위

코드에 자격별 설정을 한곳에 모으면 노무사·회계사도 같은 방식으로 추가할 수 있습니다.

1. 자격별 설정 추가: 관계, 미팅 성격, 03·04단계 문구, 저항 대응
2. 변리사일 때 신호 항목 표시와 진입로 판단
3. 세 진입로의 스크립트 문구와 PC 순서
4. 업체 분석 보고서에 지식재산 항목 표시
5. 변리사 예시 버튼 추가 (가상 회사)
6. 금지어 검사와 채점의 자격별 예외: 변리사일 때만 "직무발명"을 금지어와 구조 언급 감점에서 제외. "절세", "비과세" 경고는 유지

**완료 기준**
- 자격이 세무사이면 지금과 결과가 같다.
- 변리사 스크립트에 "기장", "결산", "기장 영업"이 나오지 않는다.
- 변리사 스크립트는 "직무발명" 외의 금지어 없이 검사를 통과하고, 세무사 등 다른 자격에서는 "직무발명"이 그대로 금지어로 잡힌다.
- 03단계 사례는 본인 경험 입력을 요구한다.
- 보험 안내가 용역 비교와 같은 장에 섞이지 않는다.

## 9. 작성 변리사가 정할 것

| 번호 | 결정 | 제 추천 |
|---|---|---|
| 1 | AP에서 "직무발명"이라는 말을 쓸지 | **결정: 변리사는 허용(작성 변리사, 2026-11-04).** 기존 팀 규칙의 예외이므로 허브 담당 동의 필요 |
| 2 | 특허 고객 없이 초면이 많은지 | 실제 비중이 큰 관계부터 문구를 다듬음 |
| 3 | 개인사업자를 포함할지. 지금 진단은 법인만 | 1차는 법인만. 개인은 세무사 확인 후 |
| 4 | 03단계에 쓸 실제 경험 2개 | 본인만 쓸 수 있어 제공 필요 |
| 5 | 특허 공개 정보 자동 조회 | 1차는 수동 입력. 자동 조회는 KIPRIS 이용 조건 확인 후 |

## 10. 확인하지 못한 것

- 06~15단계와 PC 준비 코드 전체
- 멘트의 현장 적합성(실제 RP 필요)
- 선출원 설명과 세무 요건의 최신 내용
